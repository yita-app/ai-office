# 下班

`ROOT`＝AI Office 程式的位置：本 skill 的 Base directory（SKILL.md 所在資料夾）往上兩層；如果那裡沒有 `scripts/team.sh`（例如在 Codex），改用 `cat ~/.ai-office/root` 印出的路徑。
辦公室根目錄＝`bash "ROOT/scripts/find-office.sh"` 印出的路徑。

全程自動，不用一步步問使用者；只有出錯時才停下來問。

## 1. 寫日記
如果這個 session 有上班（有名牌，例 `Mia｜行銷`），在 `team/<名字>/log.md` 最後加一筆：
```
## YYYY-MM-DD HH:MM｜<名牌>｜下班
- 這次做了什麼（重點，條列）
- 還沒做完的事、下次要接著做什麼（沒有就寫「無」）
```
寫給「下次上班的自己」看：只靠這幾行就要能接得上。⛔ 不寫鑰匙的值。
這次 session 已經寫過的日記不用重抄，只補還沒記的部分。
沒有上班過就跳過這一步。

## 2. 存檔
照 `ROOT/skills/sync/SKILL.md` 的步驟做（檢查 → commit → pull → push），不用再問使用者。
- 檢查擋下（疑似鑰匙）：⛔ 不要收起視窗，告訴使用者哪裡卡住，等他決定。
- 這個環境不能用 Git、或推不上去（例如 Codex）：沒關係，日記和檔案已經存在電腦上；照 sync 的說法講一句就好，繼續下班。
- 還沒接 GitHub：只做本機 commit，告訴使用者一句，然後繼續。

## 3. 道別，然後馬上收起視窗
像真人下班一樣，用兩三行告訴使用者：今天做了什麼、存好了、下次打 `/role <名字>` 就能找我。⛔ 不要提「座位」。
道別寫完，同一個回合裡接著做第 4 步，中間不要再做別的事。

## 4. 收起視窗
- 預設（`/off`）：有 `archive_session` 工具（桌面 App）→ 用 `session_id: "self"` 封存這個 session。之後還能從「已封存」打開。
- 使用者說「清空」：有 `clear_session` 工具 → 用 `session_id: "self"` 清空對話；視窗留著，下次在同一個視窗打 `/role <名字>` 回來。
- 沒有這些工具（終端機版）：請使用者打 `/clear`（清空）或直接關掉。
- 使用者拒絕封存／清空：沒關係，日記和存檔都已完成，說一句就好。
