# 雇用新員工

`ROOT`＝AI Office 程式的位置：本 skill 的 Base directory（SKILL.md 所在資料夾）往上兩層；如果那裡沒有 `scripts/team.sh`（例如在 Codex），改用 `cat ~/.ai-office/root` 印出的路徑。要在辦公室根目錄執行；辦公室根目錄＝`bash "ROOT/scripts/find-office.sh"` 印出的路徑（只認 `.ai-office` 檔案，不會誤認 `~/.ai-office` 設定資料夾；沒印東西＝不在辦公室裡）。

## 0. 是不是以前的員工？
先看離職區：
```bash
bash "ROOT/scripts/team.sh" alumni
```
使用者給的名字在離職區裡 → 問：「Max 以前在這裡工作過，要讓他回來（名片和日記都還在），還是重新雇一個新的？」
- 回來：`bash "ROOT/scripts/team.sh" rehire <名字>`，然後跳到第 6 步收尾。
- 新的：請他換一個名字，避免跟以前的資料搞混。

## 1. 挑職位
先列出候選職位：
```bash
bash "ROOT/scripts/team.sh" roles
```
照「編號. 職位 — 做什麼」列給使用者看，最後加一行「＋ 自訂：名單裡沒有的，自己描述要他做什麼」。
- 使用者給的參數已經對得上某個職位（例 `/hire mia 行銷`）→ 直接用那個編號，不用再問。
- 同一個職位可以雇很多人。

## 2. 取名字
- 名字規則：只能用英文字母（可以用 `-` 連接），⛔ 不能有數字；存檔時一律轉小寫。
- 不合格就建議一個合格的。
- 使用者沒想法：建議 2～3 個好記的英文名字讓他挑。
- ⛔ 不要跟這台電腦上其他 session 的名字一樣（例如舊的 `dex11`）。

## 3. 建立
- 從名單挑的：
  ```bash
  bash "ROOT/scripts/team.sh" hire <名字> --role <編號>
  ```
- 自訂：
  ```bash
  bash "ROOT/scripts/team.sh" hire <名字> "<職位>"
  ```

## 4. 引導老闆把他變成「專屬員工」（一定要做）
名單裡的職位只是**基本版**。每個老闆要的不一樣，重點是讓老闆自己定義這位員工。像帶新同事報到一樣，用白話、一步一步來：

**① 先講基本版（3～5 行）**
「Max 是廣告投放，基本上會做：……」從名片挑 3～4 個重點。自訂職位就說「Max 目前還是一張白紙」。
然後說一句：「這是基本版，接下來問你兩個問題，讓他變成你專屬的廣告投放。」

**② 問題一：要他做什麼？**
「你希望 Max 實際幫你做哪些事？」附 2～3 個**跟這個職位、這間辦公室有關**的例子（例：負責哪個品牌或產品、用哪些平台、多久跟你報告一次）。
等使用者回答，再問下一題。

**③ 問題二：他要懂什麼？**
「做這些事，Max 需要先知道哪些事情？」附 2～3 個例子（例：你的客人是誰、品牌想給人的感覺、價格或優惠、不能碰的地雷）。
使用者手邊有現成資料（網址、文件），也可以直接給。

**④ 記下來、複述確認**
- 寫進 `team/<名字>/card.md`：問題一 → 「## 老闆交代」；問題二 → 「## 我要知道的事」。條列、精簡（名片上限 3000 bytes），長的資料放 `docs/`，名片只寫一行指過去。
- `team.md` 那一行的「做什麼」改成一句符合老闆說法的話。
- 用 3～5 行複述給老闆：「好，Max 會……，他會記得……。對嗎？」有要改就改。

使用者說「之後再說」→ 沒關係，告訴他之後直接跟這位員工說就好。
任何一題答得很短也沒關係，⛔ 不要追問超過一次。

🗣️ ⛔ 不要叫使用者自己去改檔案、⛔ 不要把檔案路徑丟給使用者。檔案是員工自己用的，要改什麼「跟他說，他會自己記下來」。

## 5. 先把上班要用的東西準備好（名片有才做）
名片裡有「上班先…」的段落（例 YITA 網站的「上班先檢查連線」）→ 現在就先做**不需要使用者動手**的部分（例如檢查連線、沒接就加上）。
- 需要使用者登入的部分留到上班時再做，收尾時說一句：「第一次上班時，他會帶你登入 YITA。」
- 加了新連線 → 提醒：要**開新視窗**再叫他上班，新連線才看得到。

## 6. 收尾
兩三行就好：
- 已雇用誰、職位、主要負責什麼（用使用者剛剛說的內容）
- 想讓他上班：開一個新視窗，打 `/role <名字>`
- 之後想調整他的工作或補充他要知道的事，直接跟他說就好
